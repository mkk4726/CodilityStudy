# 피드백

## set 풀이 ([`solution.py`](solution.py))

해시로 보수(complement)를 찾는 two-sum이다. 제약(`N ≤ 1000`, 중복 없음) 안에서는 정답·복잡도 모두 충분하다.

- 이중 루프 \(O(N^2)\) 대신 집합을 한 번 만들고 \(O(1)\) 조회로 \(O(N)\)을 맞춘 점이 이 문제의 의도이다.
- `value == left`로 같은 칸을 두 번 쓰는 경우를 막은 것도 맞다. 원소가 유일하니까 `2 * value == target`이면 그 수는 하나뿐이다.
- `left <= 0`은 없어도 된다. 원소가 전부 양수라서, 그 경우는 `in`이 그냥 `False`이다. 남겨도 틀리진 않고 조기 스킵일 뿐이다.

루프마다 `continue` 두 갈래보다, 찾는 조건만 한곳에 모아도 된다.

```python
if left != value and left in set_arr:
    return True
```

집합을 미리 다 만들지 않고, 본 숫자만 `seen`에 넣으면 같은 원소 문제도 자연스럽게 사라진다. `5`를 처음 볼 때 `5`는 아직 `seen`에 없다. 시간도 \(O(N)\), 공간도 \(O(N)\)로 같고, 해시 단원에서 더 자주 나오는 형태다.

```python
seen = set()
for value in arr:
    if target - value in seen:
        return True
    seen.add(value)
return False
```

지금 풀이도 이 문제 조건에서는 충분하다. 다음에 중복이 허용되면 `value == left`만으로는 부족하고, 위처럼 “이미 본 쪽”만 조회하는 쪽이 더 안전하다.

## 교재 해시 테이블 풀이 ([`hash_table.py`](hash_table.py))

교재 코드는 Python `dict`/`set`이 아니라 **값을 인덱스로 쓰는 배열(직접 주소 지정)** 이다. `hash[num] = 1`로 “이 숫자가 있다”를 표시하고, `hash[target - num]`으로 보수를 \(O(1)\)에 본다.

### 장점

- 조회가 진짜 배열 접근이라, 충돌·해시 계산이 없다. `set`은 평균 \(O(1)\), 이론상 최악 \(O(N)\)이다.
- 해시의 핵심인 “키 → 바로 위치”가 코드에 그대로 드러난다. 교재가 해시 단원에서 이렇게 푸는 이유다.
- C/Java처럼 집합이 없거나 무거운 환경에서는 구현이 단순하고, 인덱스 접근이 캐시에도 유리하다.

### set보다 낫다고 보기는 어려운 점

공간은 `set`이 \(O(N)\)(`N ≤ 1000`)인데, 배열은 \(O(\textit{target})\)(`target ≤ 20000`)이라 오히려 더 크다. `target`이 \(10^9\)이면 배열은 메모리 때문에 못 쓰고, `set`은 그대로 된다.

### 정리

교재 풀이는 **값의 범위가 작고 고정일 때** 빠르고 가르치기 좋은 형태다. 파이썬 `set` 풀이는 범위가 커져도 쓸 수 있는 **더 일반적인 two-sum**이다. 둘 다 시간 \(O(N)\)이고, 이 제약에서는 둘 다 충분하다.
